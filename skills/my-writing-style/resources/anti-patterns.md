# Anti-patterns

아래 표현이 하나라도 있으면 다시 쓴다.

## 블로그에서는 쓰지만 Study 문서에서는 빼는 것

- 인사말: `안녕하세요`, `오늘은 ~에 대해서 알아보겠습니다`, `바로 시작해 보겠습니다`
- 맺음 인사: `감사합니다`, `다음 포스팅에서 뵙겠습니다`, `열심히 공부하겠습니다`
- 이모티콘·감탄 기호: `^^`, `:)`, `ㅠㅠ`, `~!!`, `~??`, 물결 늘이기(`알아보도록 하죠~`)
- 근황·사정 이야기: `포스팅이 늦었네요`, `학원 수업이 끝나고`
- 독자에게 묻기: `간단하죠?`, `어떠신가요?`

## 과장·근거 없는 평가

- `혁신적인`, `게임 체인저`, `놀라운`, `강력한`, `최고의`, `완벽한`, `압도적인`
- `~는 필수입니다`, `무조건 써야 합니다`
- 직접 써 보지 않은 것에 대한 성능·품질 단정 (`빠릅니다`, `안정적입니다`)
  - 출처가 있으면 `문서에 따르면 ~라고 합니다`로 쓴다.

## 늘어지는 표현

- `~하는 것 같습니다`를 사실 서술에 쓰기 (추측일 때만 쓴다)
- `~해 주도록 하겠습니다`, `~해 보도록 합시다` → `~합니다`, `~하면 됩니다`
- `있어서`, `~에 대해서` 남용: `이 기능에 대해서 알아보겠습니다` → `이 기능을 정리합니다`
- 같은 문장에 `그리고`, `또한`, `그래서`를 이어 붙여 길게 만들기

## 형식 문제

- 설명 문단과 개조식을 한 문단에서 섞기
- 정의를 문장으로 늘어놓기 (`Code Spliting은 ~하는 전략입니다.` → `- Code Spliting : ~하는 전략`)
- 코드 블록에 언어 표시 없음
- 조사 오류·오타 방치: `~이 되어지고 있는` 같은 이중 피동, `disort`(→ `distort`)
- 섹션 제목에 이모지 붙이기 (리포트 템플릿은 예외)

## 사실 관계

- Research Note에 없는 내용 추가 (숫자, 버전, 날짜, 기능)
- 출처 없는 비교: `A보다 빠릅니다`
- Star 수·다운로드 수를 반올림하거나 어림해서 쓰기

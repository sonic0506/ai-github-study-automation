01. SPA

- 라우팅(어떤 주소에 어떤 UI를 보여줄지 큐칙을 정하는 작업)을 클라이언트가 담당

- 라우팅은 예전에는 보통 서버에서 관리하는 로직

- non-SPA : 클라이언트가 url 요청시 서버에서 라우팅 처리를 하여 새로운 페이지를 보내서 보여줌 (사용자 수, 인터렉션이 많이 발생하면 문제가 생김)

- SPA : 클라이언트가 url 요청시 클라이언트에서 라우팅 처리하여 페이지를 보여주고 서버에는 필요한 데이터만 요청하여 받아와 동적으로 보여줌 (UI에 대한 정보를 클라이언트에서 다 가지고 있고 자바스크립트를 통해 변하는 데이터만 서버에 요청하여 동적으로 보여줌)

​

​

02. SPA 단점과 해결책

- 앱의 규모가 커지면 JS파일의 크기가 너무 커질 수 있음 => code spliting을 통해 해결가능

    - Code Spliting : 기능별로 파일을 분리시켜 필요한 시점에만 파일을 불러오는 전략

- 브라우저에서 자바스크립트가 구동되지 않으면 UI를 볼 수 없음 => server side rendering으로 해결가능

03. router 사용방법

- react-router : 컴포넌트를 기반으로 라우팅함

- next : 서버사이트 렌더링을 쉽게 구현 가능, 파일경로와 이름을 기반으로 라우팅함

​

​

04. 라우터 컴포넌트의 종류

- BrowserRouter : 주소만 바꾸고 페이지는 다시 불러오지 않음 (IE 6-9 작동 X)

- HashRouter : #을 사용함, 옛날 브라우저 전용

- MemoryRouter : 브라우저의 주소와 무관함, 일체 건들이지 않음 (임베디드 웹앱, 리액트 네이티브 등에서 사용)

- StaticRouter : 서버사이트 렌더링에서 사용하는 용도

- Route : 라우트를 정의할 대 사용하는 컴포넌트

- Link : 사용한 Router의 주소를 바꿈 a태그지만 새로고침 안됨
